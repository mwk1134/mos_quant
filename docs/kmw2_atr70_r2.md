# KMW2 ATR70–R2 혼합매매

웹앱의 전략 스위치는 KMW2의 **ATR70-R2 혼합매매** 하나만 표시한다. 기본값은
꺼짐이다. KMW·JEH·JEH2·KHW 및 프리셋 미선택 화면에는 전략 스위치를 표시하지 않는다.
기존 독립 정배열(V1.1-R) 스위치는 종료했으며, 과거 저장값이 켜져 있어도 새 매수에는
사용하지 않는다. 기존 보유분과 접수된 주문의 진입 당시 매도 규칙은 보존한다.
혼합 전략의 R2 내부 정배열 판정은 별도로 계속 적용한다.
이 설정을 켜도 자동매매 엔진 자체가 켜지지는 않는다. 기존 엔진 활성화와
계좌 확인 절차는 그대로 적용한다. 다른 프리셋에는 혼합 전략을 적용하지 않는다.

## 전환과 종료

스위치를 켠 뒤 기존 KMW2 보유분이 남아 있으면 `WAITING_FLAT`이다. 새 매수는
중단하고 기존 회차별 목표가·보유 만기 매도만 계속한다. 과거 시뮬레이션 결과나
매도 주문 접수만으로 잔고를 0으로 만들지 않는다.

브로커 확인 스냅샷과 실제 SOXL 잔고가 모두 0이고 미체결·활성 예약이 없으며,
USD 예수금과 추정 예수금이 일치한 뒤 해당 현금으로 ATR·R2에 각 50%를 배정한다.
기존 프리셋 초기원금 $67,612를 새 전략의 초기 자금으로 재사용하지 않는다.

사용자가 `USD_BUYING_POWER_CAP`으로 운용 원금 상한을 지정한 경우에는 추정 USD
예수금과 통합증거금을 사용하지 않은 독립 USD 주문가능금액을 함께 검증한다.
두 금액이 요청 원금 이상이고 다른 통화 담보가 0일 때 요청 원금만 50:50으로
배정한다. 초과 잔액은 전략 예산 밖에 보존하며, 매수마다 주문가능금액을 다시 확인한다.
기본 `FULL_SETTLED` 요청은 기존 예수금 일치 조건을 적용한다.

혼합 운용이 시작된 뒤 스위치를 끄면 신규 매수만 중단한다. 기존 ATR 익일 시가
청산과 R2 목표가·만기 청산은 유지한다. 기존 동파법으로 자동 복귀하지 않으며
혼합 장부를 삭제하지 않는다. 엔진 자체를 끄면 모든 자동 주문 전송이 중단된다.

## 매매와 데이터

웹앱과 자동매매 관리 화면은 **ATR70 주문표**와 **R2 주문표**를 별도로 표시한다.
웹앱은 KMW와 같은 **매수 추천 / 매도 추천** 2열 구성으로 먼저 표시하고,
각 항목에 ATR70·R2, 회차, 주문 가격·수량과 조건을 구분한다. 기존 전략별
주문표는 접힌 **전략별 주문 상세**에서 확인한다. 저장된 주문은 신규 추천
건수에 포함하지 않으며, ATR 가격·수량 미정과 시장가 예산 기준도 그대로 표시한다.
두 전략의 매수 조건이 모두 충족되면 전략별 예산·수량·주문번호로 각각 전송하며,
두 매수를 한 주문으로 합치지 않는다. ATR70의 시가·돌파가 아직 확인되지 않았다면
가격과 수량을 확정하지 않고 조건 확인 대기로 표시한다. 접수된 주문과 새 조건부
주문안도 구분한다. 스위치 OFF는 이미 접수된 주문의 취소를 뜻하지 않는다.

- ATR은 Wilder70, 전일 ATR%와 그 이전 252개 ATR%의 75백분위를 비교한다.
  비교 대상인 전일 값을 백분위 모집단에 포함하지 않는다.
- 조건 통과일의 **미국 정규장 실제 시가 × 1.015** 이상 실시간 체결에서 매수한다.
  일반 지정가를 돌파가에 미리 걸어 두는 방식이 아니다. 하루 한 번만 진입한다.
- 메리츠 정규장 WebSocket `ohhts_exst_cntg`의 거래소·SOXL·현지 거래일·실시간
  여부와 체결 시각을 확인한다. 15초보다 오래된 체결로 새 매수하지 않는다.
- ATR 매수 수량은 시장가 주문의 10% 여유 가격과 비용 여유분을 포함해 해당
  전략의 현금 안에서 계산한다. 예산은 접수 전 예약하고 실제 체결 금액으로 정산한다.
- ATR 보유분은 다음 미국 거래일 09:25 ET 이전에 MOO 매도를 접수한다.
  마감을 놓쳤으면 정규장의 확인된 가격으로 별도 시장가 청산을 시도하고,
  기존 청산이 확인되기 전에는 재진입하지 않는다. 같은 주문은 자동 재전송하지 않는다.
- R2는 완료된 QQQ 주봉의 rolling mean RSI(14)와 SOXL 5MA > 20MA > 60MA를
  사용한다. 정배열이면 V1.1-R2, 아니면 기본 동파 규칙을 적용한다.
- R2 SF: 매수 +6.25%, 목표 매도 +1.5%, 35거래일. AG: 매수 +15.25%, 목표
  매도 +6.8%, 7거래일. 진입 당시 모드·규칙을 포지션별로 보존한다.
- R2 기준시드는 1·10·20… 미국 거래일에 갱신하며 전략상 7일 지연 정산 후
  이익 72%, 손실 21.3%를 반영한다. 매수 수량은 매도대금을 미리 당겨 쓰지 않는다.
- 완료 일봉은 전체 이력의 동일 앵커로 계산한다. 누락·지연·RSI 계산 실패 시
  신규 매수는 중단하되, 이미 확정된 보유분의 청산은 별도로 관리한다.

## 월초 비중 조정

월중 비중은 고정하지 않는다. 매월 첫 미국 거래일에 ATR 전일 물량을 먼저
청산하고, 시가를 확인한 뒤 전체 자산을 ATR·R2 각 50% 목표로 조정한다.
첫 거래일 가동을 놓치면 해당 월의 다음 실행 시 먼저 조정을 진행한다.

현금 이동으로 가능하면 추가 매매하지 않는다. R2에서 ATR로 이동할 현금이
부족하면 기존 R2 물량에 비례해 필요한 최소 정수주를 매도한다. 실제 매도
체결과 비용 반영을 확인한 뒤 현금과 기준시드를 조정한다. 남은 포지션의
진입일·회차·규칙은 보존한다. 조정 중에는 신규 매수를 보류한다.

백테스트의 동일 시가 평가·즉시 체결과 달리 실거래 리밸런싱은 개장 후 실제
체결 가격을 사용한다. 시가와 실제 매도가·비용 때문에 정확히 같은 NAV가 되지는 않는다.

## 장부와 비용

`data/positions_snapshots.json`의 `KMW2.atr70_r2`가 영속 전략 장부다. 활성 장부는
기존 시뮬레이션·수동 원금 재설정·기존 체결 갱신기로 덮어쓸 수 없다.
GitHub CAS 저장 충돌 시 최신 장부를 덮어쓰거나 주문부터 먼저 보내지 않는다.
전송 의도와 `SENDING`은 저장한 뒤 전송하고, 계좌별 SQLite에 접수 기록을 남긴다.
접수 미확정·저장 미확정은 자동 재전송하지 않는다.

메리츠 주문 이력의 체결 수량·체결 대금은 실제 값이다. 해당 조회는 수수료를
제공하지 않으므로 혼합 장부의 비용은 `MERITZ_MIX_FEE_RATE`의 **추정 비용**으로
별도 표시한다. 기본값 `0.005`는 편도 0.5% 비용 여유분이며 백테스트의 0.05%와
다르다. 이를 실제 브로커 수수료로 표시하지 않는다. 실제 USD 주문가능금액도
매수마다 별도로 확인한다. 예수금 차이·외부 수동 체결을 전략 수익이나 증액으로
자동 처리하지 않는다.

## 모의 검증

실제 계좌나 주문 서버 없이 가짜 브로커·시계·시세·CAS 저장소로 실행한다.

```sh
python -m pip install -r requirements.txt pytest
python -m pytest -q tests/test_atr70_r2*.py
```

전환 대기, 미체결 차단, R2 LOC와 ATR의 동시 운용, 부분체결, 다음 거래일 MOO,
MOO 마감 이후 청산, 월초 부분매도와 현금 재배분, 재시작 중복 방지, 저장 실패,
지연 시세, 스위치 OFF, 계좌 격리 및 실제 Streamlit 화면을 검증한다.

공식 주문·시세 필드는 [메리츠 API 명세](https://openapi.imeritz.com/api-spec/download/json),
MOO 마감 등은 [미국 주문 안내](https://home.imeritz.com/mobile/content/overseas/usa.html)를 따른다.
모의 테스트는 실제 계좌의 주문 접수·체결을 보장하지 않는다.
